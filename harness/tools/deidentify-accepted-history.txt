# Accepted historical TERM findings for harness/tools/deidentify_lint.py.
#
# One entry per line: a full 40-hex commit SHA, a repository path, and a term,
# separated by whitespace. The entry suppresses only the term finding that
# matches all three fields when --history walks the commit that first carried
# that file content, and it covers that whole file version, not one line. It never applies to the current tree, to structural
# checks, or to any other path, commit, or term. An entry that matches nothing
# is reported as STALE and fails the run.
#
# An entry is allowed only for a finding in already-published history that
# cannot be rewritten (the commit must be contained in a release tag), and each
# entry is reviewed by a maintainer. The current files were reworded; these two
# commits keep the older wording. Entries are read from the copy committed at
# HEAD. This file is scanned like any other, so comments must stay free of
# private text; only the term field of an entry line is masked.
#
# The term field may be written as "sha256:" plus 64 lowercase hex characters,
# the sha256 of the lowercased term's UTF-8 bytes, so a private term can be
# accepted without being published. A digest hides the term from reading, not
# from someone who guesses it.
