# Investment web rendering

Load this reference only when `/deck-render --web` receives an investment-mode outline. The approved outline and its evidence table remain the content authority.

## Brand and audience

- Import and extend the company's brand tokens when a brand system exists. Do not replace the brand floor with a deck-scoped palette or type system.
- Mint the page for the real audience: title letterhead names who it is prepared for, from whom, and the subject.
- Include audience-specific fit only when the outline contains real recipient evidence. Renaming a generic slide is not personalization.
- Close by returning to the opening argument and naming one primary next action beside a real contact.

## Evidence and honesty

- Every number keeps its unit, time window, and cited source from the outline evidence table.
- Conceptual diagrams carry a visible `CONCEPTUAL`, `ILLUSTRATIVE`, or `SCHEMATIC` label.
- Product, demo, customer, and traction proof must be real and reachable. Never present generated imagery or a mockup as factual product evidence.
- Images follow the outline's source and license status. Unresolved licensing blocks external publishing.

## Graphic floor

Every content slide needs an argument-carrying image, chart, diagram, interface, map, icon system, or motif. The hardest skeptical claim gets a bespoke diagram. Card grids use a consistent icon vocabulary and equal geometry; the offered option is the only comparison element allowed the accent border.

## Web behavior

Use the shared 16:9 stage, navigation, reduced-motion, no-JS, accessibility, and print-safe rules from the deck-render references. Motion reveals existing evidence; it never creates meaning unavailable in the static final state. Keep the bundle self-contained with zero external runtime requests.

Publishing remains a separate external write. Build and QA do not authorize deployment or a live URL.
