# Security

## The guards are seatbelts, not locks

Every guard in this repository models a set of literal shapes and blocks or warns on those. None of them is a security boundary. Each one is bypassable by a shape it does not model, by variable expansion, by obfuscation, or by `--no-verify`. They exist to catch the honest mistake, not the determined actor. Treat them that way when you decide what else to run.

| Guard | What it does | What it does NOT catch | Caught-shape and recorded-gap fixtures |
|---|---|---|---|
| `dangerous_ops_guard` (PreToolUse hook) | Denies literal command shapes: force-push to a protected branch (including `HEAD:main` and `+main` refspecs, `git -C <dir> push`, bundled short force flags such as `-fu`, `--mirror` or `--all --force`, a quoted ref, an unquoted list of refspecs joined in one push, a bare `-f`/`--force` with no explicit refspec under main-only git mode, and remote branch deletion via `--delete <branch>` or a `:branch` refspec), recursive delete at root, home, `/*`, a system path, a `..`-relative target including `./../` and PowerShell's parent-relative `..\` form, or an unquoted Windows-style backslash path (split flags `-r -f`, long flags `--recursive --force`, coarse PowerShell `Remove-Item -Recurse -Force` shapes), `git clean -fd`, destructive SQL only when executed through a client or after `;`, a read command (`cat`, `type`, `Get-Content`, `less`, `head`, `tail`, `sed -n`, `python -c open(...)`) whose argument is a credential path, the same read command reached through `$(...)` command substitution or backticks including nested substitution, and the credential shapes `.npmrc`, `.netrc`, `.pgpass`, `.pypirc`, `.git-credentials`, `*.ppk`, `*.keystore`, `*.tfvars`, a `$HOME/`-prefixed credential path, the AWS `credentials` file under a `.aws` directory including the `credentials*` wildcard inside `.aws`, gcloud's application-default-credentials file, and an SSH private key filename (`id_*`, not `.pub`) under a `.ssh` directory. A command carrying `--dry-run` is allowed even when its base shape would otherwise be denied, and a single-quoted string that merely mentions a denied shape as prose still passes by design, except as the payload of a `bash -c`/`sh -c`-style shell invocation, where the invoked shell strips the quoting and the guard must still catch it. Every tier parses the command before classifying it: a leading wrapper (`sudo`, `env FOO=bar`, `command`, `exec`, `time`, `nice`) is stripped so the wrapped command is what gets classified, and git global options between `git` and the subcommand (`git -C <dir> push`) do not hide the subcommand. | A destructive text assembled at runtime rather than written out (variable concatenation, encoded or base64 payloads), `xargs`, `find -delete`, `rsync --delete`, any tool call the runtime does not route through PreToolUse, hosted tools the runtime does not expose to hooks, and a recursive delete whose target is relative after a `cd` in an earlier segment. Wrapping a literal shape in an alias, a shell function, `eval`, or another shell does not hide it (the scan reads the text, not the shell), but a shape those wrappers build from pieces at runtime is invisible. Prose mentions of the same strings pass by design (execution-context rule); single-quoted text is inert for every tier, not only `rm`, unless the command word is a shell running a string (`bash -c`, `sh -c`, `pwsh -Command`). The secret-exposure tier's reader list is closed and named (`cat`, `type`, `more`, `less`, `head`, `tail`, `sed`, `awk`, `Get-Content`/`gc`); a reader outside that list passes a credential path by design, including `strings`, `xxd`, `od`, `base64`, `openssl`, `sort`, `cp`, `tar`, `perl`, `grep` on a credential file, `node -e`, `python -m json.tool`, `git show HEAD:<file>`, `git diff -- <file>`, and `echo <file> | xargs cat`. Command-substitution nesting deeper than 64 levels is also a miss (the walk has a fixed recursion floor). A refspecs are classified by their destination side: `git push --force origin main:feature` is allowed, `feature:main`, `:main`, `+main`, `HEAD~1:main`, and `--delete main` deny. The guard lexes the command with shell quote state (single quotes inert, apostrophes inside double quotes literal, an unquoted `#` ends the line when it starts a token, so a `#` inside a word such as `foo#bar` is not a comment), strips environment-assignment prefixes and wrapper commands (`sudo -u x`, `env`, `nice`, `time`, `exec`, `nohup`, `doas`), parses git global options (`-c k=v`, `-C dir`) before the subcommand, treats redirection sources (`< .env`, `$(<.env)`) as read operands, keeps Windows backslash paths intact for PowerShell cmdlets and colon-bound parameters (`-LiteralPath:`), and re-classifies the string argument of a shell running a string (`bash -c`, `sh -lc`, `pwsh -Command`, `cmd /c`), of `eval`, and of an `alias` or variable assignment that holds a literal command. | `harness/hooks/tests/fixtures/guard/*` (caught shapes are `bypass-<class>.json`; each named gap above has a fixture recording its current outcome: `allow-<gap>.json` where the shape passes (variable expansion, `xargs`, `find -delete`, `rsync --delete`, a base64-decoded pipe, `cd` then glob) and `bypass-<gap>.json` where the text scan still catches the literal shape inside the wrapper (alias, shell function, `eval` of a variable holding the literal, `fish -c`)) |
| `.githooks/pre-commit` secret scan | One `git grep -E -f` over the whole staged index against the narrow patterns in `.githooks/secret-patterns.txt`; rejects secret-bearing filenames (`.env`, `*.pem`, ...) except templates; rejects staged gitlinks; blocks new binaries over the size floor; fails closed on a malformed pattern file. `.mcp.json` is in the filename block. It requires the executable bit, which bootstrap sets on POSIX and the doctor checks. A host that tracks an evidence tree on purpose lists it in `.githooks/secret-scan-exclude.txt` (one repository-relative path or glob per line), which removes those paths from the content and filename scans and nothing else. | Any secret whose shape is not in the pattern list (most passwords, most vendor formats), secrets split across lines, secrets inside encoded or compressed content (a base64 blob passes; raw binary blobs are scanned by the index-wide grep on tested git versions, and the binary fixture demonstrates that they are caught), secrets in git history before the hook was active, a raw clone that has not run bootstrap (`core.hooksPath` unset), and any commit made with `--no-verify` or `SKIP_SECRET_SCAN=1`. | `harness/hooks/tests/fixtures/precommit/*` |
| `frontmatter_guard` (PostToolUse hook, advisory) | Checks that `access:` is one of the five labels and that `allowed_collaborators` is present exactly when the label is `restricted`, on files under configured lanes. | Files outside configured lanes, files written by tools the runtime does not route through PostToolUse, content that is sensitive but labeled otherwise. | `harness/hooks/tests/fixtures/frontmatter/*` |
| `read_deny` (Claude only, shipped off) | Denies the native Read tool on files labeled `secret`. | Everything on Codex and OpenCode (labels are documentation there), Bash reads, any runtime that does not route Read through PreToolUse. | `harness/hooks/tests/fixtures/read-deny/*` |
| `write_deny` (PreToolUse, shipped off until a host sets `write_deny.globs`) | Denies Write, Edit, NotebookEdit and apply_patch targets under the host's reserved paths, case-insensitively, with Windows path tails (trailing dot or space, `::$DATA`) collapsed onto the reserved name and every patch target checked. | Every shell path to the same file (`cat >`, `tee`, `sed -i`, a heredoc, `git apply`, `mv`, `cp`), a runtime file tool outside the four matched names (an MCP file tool), a link that leaves the repository, and `.githooks/pre-commit`, which does not read `write_deny`; the backstop is the pull-request review. | `harness/hooks/tests/fixtures/write-deny/*` |
| `openpyxl_guard` (PreToolUse) | Denies a shell command that pairs `openpyxl` with `.save(` against an existing formatted workbook, including inside referenced `.py` files. | Other libraries, scripts loaded indirectly, notebooks, in-process calls. | `harness/hooks/tests/fixtures/openpyxl/*` |

Fixture names above are the contract for the hooks package; a listed bypass class without a fixture is a lint finding, not a claim.

The Claude and OpenCode deny lists, `.gitignore`, the pre-commit filename block, and the guard's credential-shape list carry the same canonical credential shapes (the exact filenames and extensions, plus the exact `credentials`/`credentials.*` and six named SSH keys); `harness/adapters/tests/test_credential_shapes.py` asserts the five stay aligned, so a shape added in one place fails the suite until it is added in the others. The guard additionally denies two broader forms at read time that the other four surfaces do not carry: any `credentials*` wildcard under `.aws` (`credentials_backup`, not only `credentials`/`credentials.*`) and any private `id_*` key under `.ssh` (`id_custom`, `id_rsa.bak`, not only the six named keys). This is a deliberate one-surface widening, not drift: the guard sees the full argument text of a live shell command and can afford a broader net, where the deny lists and gitignore are static glob lists that would rather stay narrow. `test_credential_shapes.py` carries a negative-space assertion recording that the broader forms are guard-only by design, so a future widening of the other four surfaces updates the test instead of silently drifting from it. The guard also treats any file sitting under a `secret/` or `secrets/` path segment as credential material regardless of filename, a directory-segment rule none of the other four surfaces expresses. The reverse direction also holds: Claude's `Read(**/.env.*)` deny entry and OpenCode's `"**/.env.*": "deny"` read permission have no negation mechanism, so a committed template file (`.env.example`, `.env.sample`, `.env.template`) that the guard and the pre-commit filename block both exempt is unreadable through the native Read tool on those two runtimes, even though the shell path (`Bash cat`, etc.) stays open. Two precedence orders follow from these rules directly: at the guard, the `.env.*` template exemption is checked before the `secret(s)/` segment rule and wins over it, so `cat` on a template file inside a directory named `secrets/` is allowed even though an ordinary file in that same directory would otherwise be credential material; and the guard's template match is looser than pre-commit's, so `.env.example.local` is allowed by the guard (its suffix check accepts anything starting with `example.`) but blocked by the pre-commit filename check (whose `-ivE` exemption requires the suffix to end exactly in `example`/`sample`/`template`), a real cross-surface inconsistency, not a bug to silently work around. `test_credential_shapes.py` pins all of this (the two broader-guard forms, the two native-deny-only forms, and both precedence cases) with a per-surface extras table that evaluates each surface's actual matching semantics against probe paths, and composes the pre-commit block's two piped grep stages (the `-iE` deny match and the `-ivE` template exemption) so a widened exemption pattern fails the suite instead of passing on the deny stage alone.

Generated subagent roles for shell-readonly profiles (review, extract, inspect, ops-check; "plan" is not a shell-readonly profile, plan-readonly renders read-only) use a `shell-readonly` class: no `Edit` or `Write` tool is granted, but Bash still is, on Claude Code and OpenCode, so the write scope for those roles stays instruction-only on those two runtimes. Codex has no equivalent tool-grant mechanism for its generated roles; its `sandbox_mode` read-only setting enforces the boundary instead.

For real secret coverage, add gitleaks or trufflehog in your own CI and rotate anything that ever lands in a commit. A committed secret is a compromised secret.

## Data classification

Five labels with clearance-free semantics: `public` is included in every export; `internal` means repository access; `confidential` is included only in exports at confidential or above; `restricted` requires a non-empty, validated collaborator list; `secret` is excluded from every export and, on Claude Code only, denied to the native Read tool by a hook that ships off by default. On Codex and OpenCode the labels are documentation, not enforcement.

`harness/tools/export.py` copies into a history-free destination only and applies the labels; the unlisted-path policy (`tiers.unlisted_path` in `harness/registry/structure.json`) decides what happens to files with no label. Its fuzz suite covers symlinks, binaries, files without frontmatter, dotfiles, `.git` absence in the destination, and referenced attachments.

## Permission posture

The shipped runtime configs use the minimal permission posture. CI asserts that no generated runtime config contains `bypassPermissions` or `skipDangerousModePermissionPrompt`. `.claude/settings.local.json` is the ignored per-user overlay; widen there, never in the tracked base.

## Secrets hygiene

Secrets live only in gitignored local stores (`.env` and its siblings). `harness/registry/environment.json` records variable names, locations, and sharing policy, never values, digests, presence results, or absolute home paths; its validator never opens a secret store. Config files reference variables by name.

## Reporting a vulnerability

There is no SLA. Report privately through GitHub's private vulnerability reporting on this repository (or by opening an issue titled "security contact requested" without details, if private reporting is unavailable). The maintainer aims to acknowledge within 14 days and to say in the acknowledgement whether and when a fix is planned. Because the guards are explicitly not boundaries, a report that a guard can be bypassed is a documentation finding unless the bypass contradicts a specific claim in `docs/VERIFICATION.md`; a report that a documented claim is false, or that a shipped default leaks data, is treated as a defect.
