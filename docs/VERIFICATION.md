# Verification matrix

What each mechanism maps to per runtime, and what has actually been observed versus derived from file shape. A row is `verified` only if someone ran the mechanism in a runtime and watched the outcome; everything else says so. Lint L10 rejects a row without a status from the closed set, an ISO date, a scope token, or a reproduction cell.

## Vocabulary

| Term | Meaning |
|---|---|
| `verified` | someone ran the mechanism inside the named runtime and observed the outcome; the row names the date, the scope, and the reproduction |
| `documented` | the file shape matches the runtime's documentation and offline checks pass; nothing was observed inside a runtime. This is the same claim the doctors print as their `configured` layer; the lint's closed vocabulary uses this word for it |
| `pending` | the mechanism exists but no check has been run, or a check ran and the row must be reproduced before it can flip |
| Scope `this-repo` | a file-shape or in-process check over this checkout, with no runtime launched |
| Scope `this-host` | a command run on the author's machine (Windows 11, Git Bash, CPython 3.13) with the exit code recorded |
| Scope `ci` | proven by a named job in `.github/workflows/offline-conformance.yml` on the runner's operating systems; no runtime is launched there either |
| Scope `live` | a runtime session; reserved for `verified` rows |
| Last live test | for `verified` rows, the session date. For `documented` and `pending` rows, the date the row's offline claim was last checked; no session ran |

Rows carry whichever status the evidence in their own cell supports; a row not yet exercised in a runtime session stays `documented` or `pending` until a `live` row above it says otherwise.

## Known gotchas

Each of these was hit for real during construction of this template or its predecessor, stated as the invariant rather than the incident.

1. **A materialized copy is not the source.** `.claude/settings.json`, `.codex/config.toml`, `.codex/hooks.json`, and the root `opencode.json` are independent byte copies (never hardlinks); editing one changes nothing upstream and `bootstrap --check` reports it as drift. Edit the adapter source and rerun bootstrap. The same holds for the rendered `AGENTS.md`.
2. **App-store Python aliases.** `python` and `python3` on Windows may resolve to a store stub that exits without running anything. Every wrapper, bootstrap entry, and doctor probes candidates by executing them and skips the stub. Do the same in any new wrapper; use `py` if `python` misbehaves in your own shell.
3. **Codex trust gate.** An untrusted project loads no `.codex/` configuration and no hooks, and headless `codex exec` blocks on the interactive trust prompt. Each hook definition is also approved by hash, so an edited entry needs re-approval. The project-scoped trust table is in `README.md`.
4. **Codex reads stdin.** `codex exec "<prompt>"` blocks on "Reading additional input from stdin" until stdin is closed: `< /dev/null` (POSIX), `< NUL` (cmd), or `$null |` (PowerShell).
5. **Strict runtime parsers.** Codex rejects an unknown key such as `_comment` in `hooks.json`. Every adapter schema closes its objects and rejects underscore-prefixed keys, `lint.py --schemas` validates the generated files, and CI seeds a comment key to prove the rejection. Never annotate a runtime JSON file with a comment key.
6. **Link paths must be gitignored.** Git on Windows recurses into a junction and would track the linked tree twice. The shipped `.gitignore` lists every link destination; add any new one there and in `junctions.json` together.
7. **`bash` off PATH on Windows.** Hook wrappers invoke `bash`; Git for Windows does not add it to PATH by default. Without it the runtime reports the hook as failed or silent and only the contract text governs. Bootstrap warns when it cannot find `bash`.
8. **Non-git directories and hooks path.** Bootstrap reports drift, never success, when `core.hooksPath` cannot be set because the directory is not a repository; `--check` exits 1 on "not a git repository".
9. **The guards are seatbelts, not locks.** `SECURITY.md` lists per guard what it does not catch and names the fixture that demonstrates each gap. Add a real secret scanner in your own CI.
10. **Sync clients and links.** Folder-sync clients rewrite files on save and follow junctions, breaking links and double-uploading linked trees. Keep the repository outside synced folders or use copy mode and accept the drift.
11. **PowerShell execution policy.** A default Windows install refuses `.ps1` files; use the `-NoProfile -ExecutionPolicy Bypass -File` form or set the policy once for your user.
